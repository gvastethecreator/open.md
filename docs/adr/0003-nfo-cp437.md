# ADR 0002: Decode classic `.nfo` as CP437 and show a VGA cell grid

- Status: accepted
- Date: 2026-08-26
- Decision owners: open.md maintainers

## Context

Native document access requires UTF-8. Classic scene and demoscene `.nfo`
files use IBM Code Page 437 box art on an 80-column VGA cell grid. Those
files fail `String::from_utf8`. The same extension is also used for UTF-8
Kodi/Plex metadata XML and for Windows System Information XML.

The Classic editor strips CR, renders inactive lines as Markdown, and uses
reading line-height. That path mutates CP437 files and breaks the art.

## Decision

`.nfo` stays an implicit companion. The packaged app does not register an
OS association for it.

On `.nfo` only:

1. UTF-8 XML (header starts with `<?xml` or a known media/system root) opens
   as format `text`. Edit stays available. Save stays UTF-8.
2. UTF-8 that is not XML opens as format `nfo`.
3. Bytes that are not UTF-8 decode as CP437 and open as format `nfo`.

Format `nfo` is Read and Source only (`editorKind: 'none'`). There is no
Edit. Native `save_document` rejects a `.nfo` path unless the existing file
is XML (Kodi/Windows). `.log` companions use the same view-only save rule.

CP437 graphics for `0x01`–`0x1F` and `0x7F` follow Unicode IBMGRAPH.TXT.
TAB, LF, and CR stay structural. Trailing `0x1A` is stripped on read.

The NFO canvas uses one bundled VGA webfont, cell metrics (`line-height: 1`,
no wrap, no ligatures). It ignores the wrap preference and the mono font
cycle. Theme colors stay the reader tokens.

Other companions stay UTF-8-only.

## Consequences

Classic scene files open and the art can join. XML `.nfo` files stay ordinary
text. Windows System Information remains the OS default app. Copy from the
canvas is Unicode. A later Edit/Save for CP437 needs a newline-preserving
plain surface, not Classic.
